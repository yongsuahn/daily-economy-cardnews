# 오늘의 경제 카드뉴스

매일 같은 흐름으로 경제 카드뉴스를 만들고 올리려고 만든 스킬이다. 아래 원칙에 붙은 날짜·인용은 이 흐름을 다듬으며 나온 결정이다.

## 0. 설정 읽기

먼저 `~/.config/daily-economy-cardnews/config.json` 을 읽는다. 없으면 `$S/config.example.json` 을 그 자리에 복사하고, 사용자에게 값을 채워 달라고 한 뒤 1~5단계(카드 만들기)까지만 한다. 게시·Figma 는 설정이 채워진 뒤에 한다.

- `workdir_root`: 작업 폴더를 만들 곳(`~` 를 펼친다).
- `brand`: 사용자의 브랜드·앱 이름. 카드에서 홍보하지 않는다(아래 원칙).
- `platforms`: 게시할 곳(기본 6곳). 빠진 곳은 건너뛴다.
- `accounts`·`meta`·`youtube_channel_id`: `references/publishing.md` 의 `{…}` 자리에 넣는다.
- `figma`: 8단계용. 비어 있으면 8단계를 건너뛴다.
- `notes`: 사용자가 남긴 추가 지시(예: 날짜 정한 실험 비교). 원칙과 같이 따른다.

## 지켜야 할 원칙 (사용자 지시에서 나온 것)

- **`brand`(자기 앱·서비스)와 엮지 않는다.** 순수 경제 정보 + 개인이 할 수 있는 대처법만. ("이번엔 가계부랑 연관짓지 말고")
- **실사 사진만.** 클레이 캐릭터·괴물·일러스트 금지. ("이상한 괴물 같은 거 쓰지마") 보도사진은 저작권 문제로 쓰지 않고 Midjourney 실사 생성 사진을 쓴다.
- **표지는 eyesmag 식.** 사진을 화면 가득 깔고 왼쪽 아래에 흰 굵은 두 줄 제목. 렌더러가 이미 그렇게 그린다.
- **카드에 머리글(「오늘의 경제 이슈」)·날짜·「넘겨서 보기」·쪽 번호(1/4)를 넣지 않는다.** 표지는 사진+제목만, 나머지는 주제 알약·본문·출처만. (2026-11-15 사용자 지시, 렌더러·Figma 스크립트에 반영됨)
- 이슈당 4장: 표지 → 설명 2장 → 「그럼 나는 어떻게 대비할까?」 대처법 4개.
- **2~4장도 사진을 배경으로 꽉 채운다.** 사진 위를 살짝 어둡게 하고 위·아래 그라데이션 위에 흰 제목·해설을 얹는다. 요점 상자·대처법 목록은 흰 상자 그대로. (2026-11-15 사용자 지시, 비교한 insta-cardnews 방식)
- **게시는 이슈별로 따로.** 12장을 한 게시물에 몰지 말고, 플랫폼마다 이슈별 게시물 3개로 올린다. (2026-11-12 "하나의 게시물로 올렸는데 1개씩 따로 올려줘")
- **형식: 영상 중심 플랫폼은 16초 영상, 글 중심 플랫폼은 사진 4장.** FB·IG 는 릴스(Business Suite 「릴스 만들기」로 한 번에), TikTok·YouTube 는 16초 영상, Threads·X 는 사진 4장. (2026-11-14 결정)
- 확인 안 된 의혹·보도는 "의혹", "보도" 로 표시하고 단정하지 않는다. 투자 관련 이슈엔 "투자 권유 아님" 을 붙인다.
- 게시글 끝에 "이미지는 AI 로 만든 연출 사진" 이라고 밝힌다.
- **게시는 사용자가 미리보기를 보고 승인한 뒤에만.** 공개 게시는 되돌리기 어렵다.

## 작업 폴더

`<workdir_root>/economy-cards-YYYY-MM-DD/` (오늘 날짜). 안에 `content.json`, `assets/`, `publish/` 를 둔다. 스킬 경로는 아래에서 `$S` = 이 SKILL.md 가 있는 폴더(플러그인으로 깔았으면 플러그인 캐시 안, 직접 넣었으면 `~/.claude/skills/daily-economy-cardnews`).

zsh 에서는 for 루프 안 `$n:` 같은 표현이 깨지고 복합 명령이 실패할 수 있다. 여러 줄 셸은 `sh -c` 나 스크립트 파일로 돌린다.

## 1. 이슈 고르기

WebSearch 로 오늘(한국 시간) 국내외 경제·금융 뉴스를 찾고, 한국 개인에게 영향이 큰 것 3개를 고른다. 거시(금리·물가·환율) 1, 시장·기업 1, 생활·제도·보안 1 처럼 섞이면 좋다. 숫자는 출처 두 곳 이상으로 맞춰 보고, 출처 이름은 카드의 `source` 에 적는다.

고른 3개와 한 줄 이유를 사용자에게 먼저 보여 준다. 사용자가 바꾸자고 하면 바꾼다(묻고 기다리지 말고, 보여 준 뒤 바로 다음 단계로 간다).

## 2. content.json 쓰기

`$S/assets/content-example.json` 을 복사해 형식을 그대로 따른다. 필드:

- `date` "2026.11.11", `header` "오늘의 경제 이슈" (둘 다 카드엔 안 그리고 Figma 섹션 이름·게시글에만 쓴다)
- 이슈마다 `key`(A/B/C), `tag`(카드 위 알약, 짧게), `cover`(표지 제목, `\n` 로 두 줄, 줄당 9자 안팎), `accent`·`bg`(이슈별 색: 빨강 C24E3F/F7F1EE, 초록 2B8456/EEF4F0, 파랑 2D5B8E/EDF1F6 등), `source`
- `coverFocusX`(선택, 0~1, 기본 0.5): 9:16 영상 표지에서 4:5 표지 사진을 자를 가로 위치. 피사체가 왼쪽이면 0.2, 오른쪽이면 0.8 처럼.
- `cards` 2개: `title`(두 줄 이하), `fact`(강조 한 줄), `tip`(두 줄 이하), `head`·`note`(흰 상자 안 제목·본문 두 줄)
- `todo` 4개(한 줄씩, 25자 안팎), `todoNote`(주의 한 줄)

줄바꿈은 렌더 뒤 미리보기로 확인하니, 이 단계에선 길이만 대략 맞춘다.

## 3. Midjourney 실사 사진 12장

`references/midjourney.md` 를 읽고 따른다. 키는 A1~C4(숫자 = 카드 번호), 표지 1번은 `--ar 4:5`, 나머지는 `--ar 4:3`. 이슈별 접촉 시트로 컷을 고르고 원본 PNG 를 `<workdir>/assets/A1.png` … 로 받는다. 사용한 프롬프트와 고른 컷은 `<workdir>/midjourney-prompts.txt` 에 남긴다.

## 4. 렌더·미리보기

```sh
swift $S/scripts/render.swift <workdir>      # macOS 전용(AppKit). → A-01.png … C-04.png (1080x1350) + vertical/A-01.png … (1080x1920)
sh $S/scripts/preview.sh <workdir>           # → preview.png, preview-vertical.png (4x3 격자)
```

`preview.png`·`preview-vertical.png` 와 문제 있어 보이는 카드를 Read 로 직접 본다. 4:5 는 사진 게시(Threads·X)·Figma 용, 9:16 은 영상(릴스·Shorts·TikTok) 용으로 화면을 꽉 채운다(2026-11-15 사용자 결정). 9:16 은 플랫폼 버튼·설명이 가리는 아래 약 350px·오른쪽 약 130px 에 글을 두지 않게 짜여 있고, 표지는 4:5 사진 가운데를 잘라 쓰니 피사체가 잘리면 `coverFocusX` 를 고친다. 확인할 것: 한 글자만 다음 줄로 넘어간 줄(예 "요."), 상자 밖으로 넘친 글, 표지 제목이 사진의 밝은 부분과 겹쳐 안 읽히는지. 고칠 땐 문장을 줄이고 다시 렌더한다.

## 5. 게시글·영상

이슈별로 따로 올리므로 본문도 이슈별로 만든다. `<workdir>/publish/split/` 에 키(A/B/C)마다:

- `<키>-long.txt` — FB·IG·TikTok·YouTube 설명용. 첫 줄 "<표지 제목 한 줄> <이모지> (YYYY.MM.DD 경제 이슈 ①)" (TikTok 제목 칸 90자에 들어가게), 해설 두세 문단, 「그럼 나는 어떻게 대비할까?」 ✔️ 4개, 출처, 필요하면 "투자 권유 아님", "이미지: Midjourney로 생성한 연출 사진(실제 보도사진 아님)", 해시태그 7개 안팎. 2200자 이하. YouTube 설명이라 `<` `>` 금지.
- `<키>-threads.txt` — 500자 이하 요약판.
- `<키>-yt-title.txt` — 100자 이하. 형식 `<핵심 한 줄> | 오늘의 경제 이슈 YYYY.MM.DD`.

그리고 `publish/` 에:

- `x-thread.txt` — 이슈별 3개 글을 `---` 줄로 나눈다(X 는 원래 이슈별 4장 스레드). `python3 -I $S/scripts/xlen.py <file>` 로 각 글이 280 이하인지 확인.
- 영상: `sh $S/scripts/make-video.sh <workdir>` → `publish/issue-A-16s.mp4` … C. `vertical/` 9:16 카드를 그대로 이어 붙인다(흐린 배경 없음).
- 표지 썸네일: 영상마다 첫 프레임을 `publish/cover-<키>.png` 로 뽑아 둔다(`ffmpeg -ss 0 -i publish/issue-<키>-16s.mp4 -frames:v 1 publish/cover-<키>.png`). FB·IG 릴스·YouTube 썸네일을 이걸로 지정한다 — 기본값은 중간 화면이고 릴스는 게시 뒤 못 바꾼다.
- `게시글.txt` 는 위 본문을 한데 모은 사람이 보는 사본, `SNS-카드뉴스-12장.zip` 은 카드 12장 압축.

## 6. 사용자 확인 (멈추는 곳)

이게 사용자의 **최종 검토** 지점이다. `open <workdir>` 로 Finder 를 열고, 이슈 3개 제목·preview 경로·게시할 곳 6개를 짧게 알린 뒤 **게시해도 되는지 묻는다.** 사용자가 처음부터 "만들어서 올려줘" 라고 했어도 여기서는 한 번 확인받는다(공개 게시라서). 카드만 원한 경우엔 여기서 끝낸다.

## 7. 6곳 게시와 확인

`config.json` 의 `platforms` 에 있는 곳만 올린다.

`references/publishing.md` 를 읽고 플랫폼마다 이슈별 게시물 3개를 **③ → ② → ① 순서**로 올린다(최신 글이 맨 위에 보이니 ① 이 맨 위에 오게). 순서는 FB+IG 릴스(Business Suite 한 번에) → Threads → X → TikTok 영상 → YouTube. 각 곳마다 URL 을 열어 실제로 올라갔는지 확인하고, 결과를 `publish/publish-results.txt` 에 쓴다. 실패하거나 확인 못 한 곳은 그대로 보고한다(예: YouTube 일일 한도, TikTok 검토 중).

## 8. Figma 월 페이지에 제작 기록

게시와 결과 파일 작성이 끝나면 바로 이어서 한다. `references/figma.md` 를 읽고 따른다. 순서는 다음과 같다.

1. `figma-build.py` 로 제작 스크립트를 만든다.
2. `use_figma` 로 실행해 섹션과 레이어를 만든다.
3. `upload_assets` 와 `figma-upload.sh` 로 사진 12장을 채운다.
4. 스크린샷으로 확인한다.

게시 결과(링크)가 섹션 안에 들어가므로 7단계보다 먼저 하지 않는다.

마지막으로 사용자에게 이슈별 6곳 URL 목록(18개)과 Figma 섹션 링크를 보여 준다.
